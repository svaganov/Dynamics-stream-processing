# План: запуск «всё в Docker» одной командой

Цель: `docker compose up -d` на чистой Windows/Linux-машине с Docker —
и через пару минут панель работает, включая подслушку A/B и сборку образа
воркера. Без Python и FFmpeg на хосте.

## Что уже есть (не трогаем)

- `app/Dockerfile` — панель в контейнере, том `/data` для реестра.
- `docker-compose.yml` в корне — панель + `docker.sock` + `extra_hosts`.
- `worker/Dockerfile` — образ воркера `audio-worker:2.4.2`.

## Этап A. FFmpeg в образе панели (подслушка A/B)

1. `app/Dockerfile`: `apt-get update && apt-get install -y --no-install-recommends ffmpeg`.
   - Подслушка: вход AAC/MP3 → выход MP3 (`libmp3lame`) — Debian-сборки хватает.
   - FFmpeg-движок в контейнере работает на нативном `aac` (уже есть вариант
     кодека в модели); `libfdk_aac` остаётся преимуществом хостовой full-сборки.
2. Проверка: в контейнере панели раздел 08 видит `ffmpeg -version`;
   подслушка A/B звучит на демо-станции.

## Этап B. Автосборка образа воркера при старте панели

1. `app/Dockerfile`: `COPY worker/ /worker_build/` (контекст сборки образа
   воркера — внутрь образа панели; ~1 КБ, это один Dockerfile FROM
   `savonet/liquidsoap:v2.4.2`).
2. `app/app.py` при старте: если Docker API доступен и образа `WORKER_IMAGE`
   нет — `docker.images.build(path="/worker_build", tag=WORKER_IMAGE)`
   (контекст уходит демону tar-потоком, пути хоста не нужны).
   Лог в консоль панели: «собираю образ воркера…» / «уже есть».
3. Флаг отключения: `WORKER_AUTO_BUILD=0` (если образ приезжает из registry).
4. Юнит-тест: мок docker-клиента — образ есть (build не зовётся),
   образа нет (build вызван с нужным тегом).

## Этап C. Упрощение compose и README/инструкции

1. Убрать сервис `worker` с профилем `tools` (сборку берёт на себя п. B)
   или оставить как ручной override — решить при реализации.
2. `docker-compose.yml`: том `./data:/data` оставить; добавить комментарий
   «одна команда — всё».
3. Обновить «Инструкция по установке»: сценарий «чистая машина с Docker» =
   установить Docker → склонировать репо → `docker compose up -d`.
4. (Опционально, отдельным решением) профиль `icecast` с контейнером
   Icecast для полностью автономного стенда без внешнего сервера.

## Этап D. Проверки

1. Полная чистовая: `docker rmi audio-worker:2.4.2 audio-panel:2.0`,
   `docker compose up -d --build` → образ воркера собрался сам, станция
   стартует, карточка зелёная, подслушка звучит.
2. Регрессия хостового запуска: `run.bat` / `python app.py` на Windows —
   юнит 55/55 и песочница 8/8 без изменений.
3. Linux-синтаксис compose проверить линтером (`docker compose config`).

## Риски и оговорки

- Пулл `savonet/liquidsoap:v2.4.2` и `python:3.12-slim` при первом запуске —
  сотни МБ, нужен интернет.
- Docker-outside-of-Docker (панель оркестрирует через `docker.sock`) —
  проверенная схема, уже работает; воркеры остаются контейнерами хостового
  демона, как и сейчас.
- Действительно «чистый» Linux (без Docker Desktop) в этой комнате не
  проверим — только синтаксис; первая проверка — на вашей Linux-машине.
