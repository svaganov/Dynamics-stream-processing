# Мультипоточная панель обработки аудио · FFmpeg / Liquidsoap → Icecast

Локальный веб-интерфейс для независимой обработки N аудиопотоков и отправки их на Icecast.
Каждая станция получает собственный изолированный пайплайн, движок выбирается per station:

- **FFmpeg** (Этап 1) — отдельный процесс `ffmpeg` на станцию, работает на Windows;
- **Liquidsoap** (Этап 2) — Docker-контейнер `audio-worker-<id>` на станцию, требует Docker
  (Docker Desktop на Windows, Linux-хост или WSL2).

Оба движка гоняют одну и ту же цепочку:

**источник AAC / HE-AAC / MP3 → эквалайзер → усиление → компрессор → нормализация громкости (LUFS) → лимитер → AAC → Icecast**.

Модель данных станции одинакова для обоих движков — меняется только способ запуска.

Панель управляет жизненным циклом каждого пайплайна: старт / стоп / перезапуск, автоперезапуск
при падении, независимые логи и счётчики рестартов, A/B-прослушка, предпросмотр команды
(FFmpeg) или сгенерированного `.liq` (Liquidsoap). Падение одной станции не останавливает остальные.

## Требования

**Движок FFmpeg (Этап 1, Windows):**

- **Python 3.9+** — https://www.python.org/downloads/ (при установке отметить «Add python.exe to PATH»)
- **FFmpeg** — full-сборка с https://www.gyan.dev/ffmpeg/builds/ (в ней есть `libfdk_aac`).
  Либо укажите путь к `ffmpeg.exe` в разделе «08 Служба».

**Движок Liquidsoap (Этап 2):**

- **Docker** — Docker Desktop на Windows (с WSL2-backend) или Docker на Linux-хосте.
- Образ воркера `audio-worker:2.4.2` собирается из `worker/Dockerfile`
  (базовый образ `savonet/liquidsoap:v2.4.2`). Имя образа можно переопределить
  переменной окружения `WORKER_IMAGE`.
- Панель оркестрирует воркеров через Docker API: при запуске в контейнере
  (`docker compose`) в него монтируется `docker.sock`; при запуске напрямую
  (`python app.py`) используется локальный демон Docker.

## Запуск

**Вариант A — панель напрямую (движок FFmpeg, Windows):**

Дважды кликните **`run.bat`** — он установит зависимости, поднимет сервер и откроет
панель в браузере: http://127.0.0.1:8770

Вручную:

```bat
pip install -r requirements.txt
python app.py
```

**Вариант B — контейнеры (docker-compose, движок Liquidsoap):**

```bat
docker compose up -d --build
```

Поднимается контейнер панели (`audio-panel:2.0`, порт 8770) и собирается образ воркера.
Сами воркеры compose не запускает — панель создаёт по одному контейнеру `audio-worker-<id>`
на каждую станцию с движком Liquidsoap.

Для управления удалённым демоном Docker (Linux-хост в сети):

```bat
set DOCKER_HOST=tcp://remote-host:2376
docker compose up -d --build
```

или `docker compose -H tcp://remote-host:2376 up -d --build`.

## Использование

1. Выберите станцию селектором в шапке. Кнопки старта, остановки и настройки действуют
   только на выбранную станцию.
2. **+ Поток** создаёт новую станцию по шаблону. **Удалить** останавливает и удаляет
   только выбранную станцию.
3. **01 Источник** — URL входного потока, переподключение при обрыве.
4. **02 Эквалайзер** — 10 полос (31 Гц … 16 кГц), пресеты, усиление ±24 дБ после EQ
   (применяется до компрессора; работает на обоих движках). Нулевые полосы в команду не попадают.
5. **03 Компрессор** — порог, ratio, attack/release, makeup gain.
6. **04 Громкость** — целевая громкость EBU R128 (−16…−14 для интернет-радио), True Peak.
7. **05 Лимитер** — потолок в dBTP, защита от клиппинга после AAC.
8. **06 Кодирование** — кодек, битрейт, частота дискретизации, каналы.
9. **07 Icecast** — хост, порт, точка монтирования, логин/пароль source-клиента.
10. **08 Служба** — автоперезапуск, общий путь к FFmpeg, **выбор движка**
    (`FFmpeg-процесс` / `Liquidsoap-воркер`). Для Liquidsoap требуется доступ к Docker.
11. **09 Прослушка A/B** — вход и выход выбранной станции через отдельный MP3-мониторинг.
12. **10 Команда** — итоговая команда FFmpeg или сгенерированный `.liq` с замаскированным паролем.
13. **11 Лог** — живой вывод процесса / контейнера выбранной станции.

**BYPASS** обходит обработку выбранной станции: поток декодируется и кодируется без фильтров.

## Конвейер Liquidsoap (один воркер)

Панель генерирует `.liq` из параметров станции (`app/liq.py`) и монтирует его
в контейнер как `/station.liq`:

```text
input.http (max_buffer 10 c, reconnect)                       приём + декод
  ├─ (ветка proc) ffmpeg.raw.encode.audio                     обёртка EQ-графа
  │   → ffmpeg.filter.equalizer ×10 полос                     EQ
  │   → ffmpeg.raw.decode.audio                               обратно в PCM
  │   → amplify(panel_gain(), proc) (опционально)             усиление, live
  │   → ffmpeg.raw.encode.audio → граф динамики → decode      компрессор → loudnorm → лимитер
  └─ switch(track_sensitive=false, panel_bypass)              live-BYPASS: вход ↔ обработка
  → output.icecast (fallible=true)                            FDK-AAC → ADTS → Icecast
```

Особенности, выясненные при портировании:

- ffmpeg-фильтры в Liquidsoap работают только поверх raw-формата: источник оборачивается
  в `ffmpeg.raw.encode.audio`, обработка — вложенными вызовами фильтров поверх графа
  (let-переменные неизменяемы), выход — через `source({audio=…, metadata=…, track_marks=…})`
  и `ffmpeg.raw.decode.audio`. Метаданные ICY проходят сквозь конвейер без изменений.
- `loudnorm` в динамическом режиме (`linear=false`) — пригоден для live-потоков.
- Пороги acompressor/alimiter переводятся из дБ в линейные значения (10^(dB/20)).
- Каждый вызов `on_metadata` печатает теги источника (`[metadata] …`) в лог воркера —
  StreamTitle виден в панели.
- Кодирование — FDK-AAC: `%fdkaac(channels=2, samplerate=44100, bitrate=128, afterburner=true)`.

Изоляция: каждый воркер — отдельный контейнер со своим watchdog, логом, счётчиком
рестартов и своим BYPASS. Открытых портов у воркера нет: он тянет источник снаружи
и пушит на Icecast наружу. Единственное исключение — telnet-сервер управления
Liquidsoap: `settings.server.telnet` на порту 1234, публикуется на хосте строго
на `127.0.0.1` со случайным портом (панель находит его через Docker API).

## Живое управление работающим воркером (Liquidsoap, без перезапуска)

В сгенерированном скрипте усиление — интерактивная переменная
`panel_gain = interactive.float("panel_gain", <линейное>)`, применяемая через
`amplify(panel_gain(), proc)` после EQ и до компрессора. Все 10 полос EQ —
тоже интерактивные переменные `panel_eq_<частота>` (включая нулевые полосы:
их можно поднимать с нуля живьём). Обработанный сигнал собирается в отдельную
ветку `proc`, а выход воркера — `switch` на переменной `panel_bypass`:
переключатель BYPASS в шапке панели работает живьём для запущенной
Liquidsoap-станции. Кнопка **«⚡ Живьём»**, слайдеры/пресеты EQ и переключатель
BYPASS шлют:

```text
POST /api/streams/<id>/adjust      {"gain_db": 3.0}
POST /api/streams/<id>/adjust      {"eq_gains": [0,0,6,0,0,0,0,0,0,0]}
POST /api/streams/<id>/bypass      {"enabled": true|false}
  → 200 {"ok": true, "mode": "live", ...}
  → 409 (движок FFmpeg / воркер не запущен / ошибка telnet)
  → 400 (нет ни gain_db, ни eq_gains у /adjust; неверный список eq_gains)
```

Панель переводит дБ в линейное (`10^(dB/20)`, диапазон ±24 дБ) и выполняет
`var.set panel_gain = <линейное>` / `var.set panel_bypass = true|false` по
telnet; значение одновременно сохраняется в `streams.json`, чтобы рестарт
поднялся с ним. Ограничения:

- только движок `liquidsoap`; для FFmpeg изменения применяются при перезапуске;
- работает только при локальном демоне Docker: при `DOCKER_HOST` порт мапится
  на удалённом хосте и живьём не достичь — API вернёт 409;
- live-BYPASS появляется в скрипте, только если в цепочке есть хотя бы один
  включённый этап обработки (иначе обход уже и так полный);
- `buffer(proc)` во второй ветке switch разводит clock-контекст ffmpeg-графов
  (иначе Liquidsoap падает с «Cannot unify two nested clocks»).

## Реестр станций

Настройки хранятся в `streams.json` рядом с `app.py` (в контейнере — на томе `/data`):

- `settings.ffmpeg_path` — общий путь к FFmpeg;
- `streams` — независимые станции: `id`, `name`, `engine` (`ffmpeg` | `liquidsoap`),
  `bypass`, источник, EQ, компрессор, громкость (`gain`), LUFS, лимитер,
  кодирование, Icecast, автоперезапуск.

Если обнаружен старый одиночный `config.json`, он однократно мигрирует в `station-1`;
исходный файл не удаляется. Старые HTTP-маршруты `/api/config`, `/api/start`, `/api/status`,
`/api/logs` и `/api/listen/<which>` продолжают работать с первой станцией.

Переменные окружения:

| Переменная           | Назначение                                             |
|----------------------|--------------------------------------------------------|
| `HOST` / `PORT`      | адрес и порт панели (по умолчанию 127.0.0.1:8770)      |
| `STREAMS_PATH`       | путь к `streams.json` (в compose — `/data/streams.json`) |
| `LEGACY_CONFIG_PATH` | путь к старому `config.json` для миграции              |
| `WORKER_RUNTIME_DIR` | каталог рантайм-скриптов `.liq` воркеров; путь должен быть виден демону Docker |
| `WORKER_IMAGE`       | образ воркера Liquidsoap (по умолчанию `audio-worker:2.4.2`) |
| `DOCKER_HOST`        | удалённый демон Docker, напр. `tcp://host:2376`        |

Основные маршруты:

```text
GET/POST       /api/streams
GET/PUT/DELETE /api/streams/<id>
POST           /api/streams/<id>/start|stop|restart
GET            /api/streams/<id>/status|logs|listen/<input|output>
POST           /api/streams/<id>/command
GET            /api/health
GET/PUT        /api/settings
```

## Проверки

После установки зависимостей:

```bat
python -m unittest discover -s tests -v
```

Unit-тесты используют временный реестр и мок-процессы FFmpeg / мок-клиент Docker,
не трогая пользовательский `streams.json`.

Песочницы (end-to-end, требуют локальный FFmpeg и Docker):

```bat
python tests\sandbox_integration.py    :: Этап 1: N станций на процессах FFmpeg
python tests\sandbox_liquidsoap.py     :: Этап 2: FFmpeg-станция + Liquidsoap-воркер
```

Обе поднимают синтетический AAC-источник, панель и фейковый Icecast и проверяют:
пуш валидного ADTS, прохождение StreamTitle, изоляцию станций друг от друга,
автоперезапуск и маскировку пароля.

## Автозапуск в Windows

- Простой вариант: ярлык на `run.bat` в «Автозагрузке» (Win+R → `shell:startup`).
- Как служба (без окна консоли): **NSSM** —
  `nssm install AudioPanel "C:\Python312\python.exe" "C:\path\to\app.py"`.
- Контейнерный вариант: `docker compose up -d` (панель поднимется сама, см. restart-политику).

## Примечания

- Панель слушает только `127.0.0.1` — снаружи недоступна. Пароли Icecast хранятся
  в `streams.json` в открытом виде: не раздавайте этот файл.
- Порядок фильтров важен: эквалайзер → усиление → компрессор → loudnorm → лимитер.
  Лимитер стоит последним, чтобы нормализация не поднимала пики после ограничителя.
- Изменения настроек применяются при следующем (пере)запуске выбранного пайплайна.
- Усиление (`gain`, дБ) настраивается в карточке «02 Эквалайзер» и применяется
  обоими движками в одной точке цепочки: после EQ, до компрессора.
- Тег `StreamTitle`: у FFmpeg-станций панель публикует его через metadata-relay
  (`GET /admin/metadata?mount=…&mode=updinfo&song=…`), т.к. FFmpeg при выходе `-f adts`
  не вставляет динамические in-band метаданные. У Liquidsoap-воркеров метаданные идут
  сквозь конвейер автоматически и публикуются клиентом `output.icecast` самим сервером.
- Telnet API воркера поднят: живая подстройка усиления и полос EQ (`/adjust`,
  кнопка «⚡ Живьём», слайдеры EQ) и живой BYPASS (`/bypass`, переключатель
  в шапке) — см. раздел выше.
- В песочнице Liquidsoap-потребление источника идёт быстрее realtime
  (авто-синхронизация под медленный источник не срабатывает) — компенсируется
  троттлингом источника в тесте. Против реального Icecast проверено не было.

## Структура

```text
app.py               — сервер Flask, реестр станций, ProcessManager и DockerWorkerManager
liq.py               — генератор .liq из модели станции (+ маскировка пароля)
static/index.html    — интерфейс панели
static/app.js        — логика мультипоточного интерфейса
streams.json         — реестр станций (создаётся автоматически)
requirements.txt     — зависимости Python (flask, docker)
run.bat              — запуск в Windows
Dockerfile           — образ панели audio-panel:2.0
../worker/Dockerfile — образ воркера audio-worker:2.4.2 (Liquidsoap)
../docker-compose.yml— панель + сборка образа воркера
../tests/test_app.py — автотесты реестра, API и изоляции процессов
../tests/test_liq.py — автотесты генератора .liq и диспетчеризации движка
```
