# Мультипоточная панель обработки аудио · Liquidsoap → Icecast

Локальный веб-интерфейс для независимой обработки N аудиопотоков и отправки их на Icecast.
Каждая станция получает собственный изолированный пайплайн — Docker-контейнер
`audio-worker-<id>` с Liquidsoap-воркером (требуется Docker: Docker Desktop на Windows
с WSL2-backend или Docker на Linux-хосте).

Цепочка обработки воркера:

**источник AAC / HE-AAC / MP3 → эквалайзер → усиление → компрессор → нормализация громкости (LUFS) → лимитер → live-BYPASS → резерв при обрыве входа → AAC (FDK) → Icecast**.

Панель управляет жизненным циклом каждого пайплайна: старт / стоп / перезапуск, автоперезапуск
при падении, независимые логи и счётчики рестартов, A/B-подслушка, предпросмотр
сгенерированного `.liq`. Падение одной станции не останавливает остальные.

## Требования

> Быстрая установка с нуля — см. [Инструкция по установке](../Инструкция%20по%20установке.md) в корне репозитория.

- **Docker** — Docker Desktop на Windows (с WSL2-backend) или Docker на Linux-хосте.
- Образ воркера `audio-worker:2.4.2` собирается из `worker/Dockerfile`
  (базовый образ `savonet/liquidsoap:v2.4.2`). Имя образа можно переопределить
  переменной окружения `WORKER_IMAGE`.
- **FFmpeg** — нужен только для подслушки A/B (MP3-мониторинг в браузер);
  full-сборка с https://www.gyan.dev/ffmpeg/builds/ или путь к `ffmpeg.exe`
  в разделе «08 Служба». Для запуска панели на хосте — **Python 3.9+**.
- Панель оркестрирует воркеров через Docker API: при запуске в контейнере
  (`docker compose`) в него монтируется `docker.sock`; при запуске напрямую
  (`python app.py`) используется локальный демон Docker.

## Запуск

**Вариант A — панель напрямую на хосте (Windows / Linux):**

Дважды кликните **`run.bat`** — он установит зависимости, поднимет сервер и откроет
панель в браузере: http://127.0.0.1:8770

Вручную:

```bat
pip install -r requirements.txt
python app.py
```

**Вариант B — панель в контейнере (docker-compose):**

```bat
docker compose up -d --build
```

Поднимается контейнер панели (`audio-panel:2.0`, порт 8770) и собирается образ воркера.
Сами воркеры compose не запускает — панель создаёт по одному контейнеру `audio-worker-<id>`
на каждую станцию. Обработка всегда идёт через Liquidsoap-воркеров (единственный
движок); FFmpeg на хосте используется только для подслушки A/B.

Два пути, о которых нужно знать при запуске панели в контейнере (оба закрыты
в `docker-compose.yml`, на Linux-хосте с монтированием `data:/data` работает
«из коробки»):

- **Bind source рантайм-скриптов.** Демон Docker резолвит bind source `.liq`
  на хосте, а `/data/runtime` внутри контейнера панели ему не виден. Если пути
  не совпадают, задайте `WORKER_BIND_ROOT` — хостовый путь того же каталога
  (на Docker Desktop Windows — Windows-путь тома, см. пример в compose).
- **Живая подстройка.** Telnet-порты воркеров публикуются на loopback хоста;
  панель внутри контейнера достаёт их через `host.docker.internal`
  (`extra_hosts: host-gateway` в compose, определение «внутри контейнера» —
  по `/.dockerenv`).

Для управления удалённым демоном Docker (Linux-хост в сети):

```bat
set DOCKER_HOST=tcp://remote-host:2376
docker compose up -d --build
```

или `docker compose -H tcp://remote-host:2376 up -d --build`.

## Использование

Панель — два представления с hash-маршрутизацией (`#/` и `#/s/<id>/<вкладка>`):

1. **Дашборд потоков** (`#/`) — главная страница: карточки всех настроенных
   входных потоков. На карточке: имя и id, статус (работает/остановлено),
   входной URL и выход `icecast://…`, аптайм, число рестартов,
   чипы цепочки обработки (EQ → GAIN → COMP → LUFS → LIM) и быстрые кнопки
   **Старт / Перезапуск / Стоп**. Статусы обновляются поллингом каждые 2 с.
   Клик по карточке проваливает в страницу станции. **+ Поток** создаёт новую
   станцию и сразу открывает её настройки.
   На каждой карточке — кнопки прослушки **🎧 A · вход** и **🎧 B · выход**
   (отдельная нижняя строка карточки): тот же мониторинг, что и в разделе
   «Подслушка A/B» страницы станции; канал один на всю панель — повторный
   клик останавливает, клик по другой кнопке переключает. Звучащая кнопка
   подсвечена зелёным.
   Работающая карточка подсвечена по состоянию тракта (легенда — в хэдере
   дашборда): **зелёная** — есть и вход, и выход; **жёлтая** — вход идёт,
   но выход не подключён к Icecast; **красная** — входной поток оборвался.
   Состояния — живые опросы воркера (`input.status` и флаг
   `panel_ice_connected` по постоянной telnet-сессии). Неизвестное состояние
   (старый скрипт воркера) аварией не считается.
2. **Страница станции** (`#/s/<id>/processing|output|system`) — настройки
   выбранного потока. В хэдере: кнопка **← Потоки** назад на дашборд, имя
   станции и кнопки Старт/Перезапуск/Стоп. Под хэдером — отдельная панель
   станции: вкладки разделов (**Обработка / Вывод и контроль / Команда
   и лог**, см. ниже) и переключатель **BYPASS**.
   **Удалить** останавливает и удаляет только выбранную станцию.
   **Имя потока редактируется**: клик по имени в шапке открывает инлайн-поле
   (Enter/фокус в сторону — сохранить, Esc — отмена); новое имя сразу видно
   в шапке, на карточке дашборда и в реестре.
   В правой панели Stream Info строка **Выход** — ссылка: клик открывает
   вкладку «Вывод и контроль» с формой Icecast (выходной поток, включая
   внешний сервер, правится там: хост, порт, маунт, логин/пароль;
   применяется при перезапуске станции).

Разделы страницы станции:
3. **01 Источник** — URL входного потока, переподключение при обрыве,
   **резерв при обрыве входа** (Liquidsoap-воркер): чекбокс «Резерв при обрыве
   входа» и режим заглушки — *тишина* (`blank()`), *тон 880 Гц* (тихий,
   ≈ −26 дБ — «техническая пауза») или *запасной URL* (бесконечный источник
   `buffer(single(...))`; loopback-адреса переписываются на
   `host.docker.internal` так же, как URL источника). В скрипте это
   `fallback(track_sensitive=false, [s, stub])` после live-BYPASS перед
   `output.icecast`: при обрыве входа эфир и слушатели не отваливаются,
   при возврате источника поток переключается обратно автоматически.
   Применяется при перезапуске станции.
4. **02 Эквалайзер** — 10 полос (31 Гц … 16 кГц), пресеты, усиление ±24 дБ после EQ
   (применяется до компрессора). Нулевые полосы в скрипт не попадают.
5. **03 Компрессор** — порог, ratio, attack/release, makeup gain.
6. **04 Громкость** — целевая громкость EBU R128 (−16…−14 для интернет-радио), True Peak.
7. **05 Лимитер** — потолок в dBTP, защита от клиппинга после AAC.
8. **06 Настройка Кодирования** — кодек, битрейт, частота дискретизации, каналы.
9. **07 Настройка подключения к Icecast** — хост, порт, точка монтирования, логин/пароль source-клиента.
   Применяется при перезапуске станции. Для Liquidsoap-воркера адреса
   `127.0.0.1`/`localhost` (и в URL источника) автоматически переписываются
   в скрипте на `host.docker.internal`: из контейнера loopback — это сам
   контейнер, а сервер на той же машине остаётся достижимым. Реестр хранит
   адреса как заданы. Под полями — живой **статус подключения выхода**:
   «Подключено к Icecast» (зелёный) / «Нет подключения — воркер повторяет
   попытки» (красный) / «воркер остановлен». Для Liquidsoap статус — это
   флаг `panel_ice_connected`, который выставляют колбэки
   `on_connect`/`on_disconnect` выхода `output.icecast` (панель читает его
   по telnet вместе со статусом станции, по ПОСТОЯННОЙ telnet-сессии —
   отдельное подключение на каждый опрос засыпало бы лог воркера строками
   «New client / disconnected»).
10. **08 Служба** — автоперезапуск, общий путь к FFmpeg (для подслушки A/B).
    Воркеры требуют доступ к Docker.
11. **09 Подслушка A/B** — вход и выход выбранной станции через отдельный
    MP3-мониторинг. Живой индикатор статуса: «звук идёт N с» (зелёный) —
    поток дошёл до браузера (если звука не слышно, проверяйте заглушенную
    вкладку и микшер); «поток не идёт» (красный) — проблема в тракте
    панель→браузер или в источнике.
12. **10 Команда** — сгенерированный `.liq`-скрипт воркера с замаскированным паролем.
13. **11 Лог** — живой вывод процесса / контейнера выбранной станции.

**BYPASS** обходит обработку выбранной станции: поток декодируется и кодируется без фильтров.

## Конвейер Liquidsoap (один воркер)

Панель генерирует `.liq` из параметров станции (`app/liq.py`) и монтирует его
в контейнер как `/station.liq`:

```text
input.http (max_buffer 10 c, reconnect)                       приём + декод
  ├─ raw_input = s                                            сырой вход для ветки BYPASS
  ├─ (цепочка секций; каждая — stage + свой живой switch)     EQ → усиление → компрессор → loudnorm → лимитер
  │   eq_stage = filter.iir.eq.peak ×10 полос                 EQ, gain-геттеры, live
  │   s = switch(panel_eq_on): eq_stage ↔ s                   живой вкл/выкл секции
  │   gain_stage = amplify(panel_gain, s)                     усиление, live
  │   s = switch(panel_gain_on): gain_stage ↔ s
  │   comp_stage = compress(threshold/ratio/attack/release/gain, s)  компрессор, live (нативный)
  │   s = switch(panel_comp_on): comp_stage ↔ s
  │   ln_raw = ffmpeg.raw.encode.audio → loudnorm             единственный ffmpeg-фильтр
  │   ln_stage = ffmpeg.raw.decode.audio → buffer(ln_stage)
  │   s = switch(panel_ln_on): ln_stage ↔ s                   живой вкл/выкл loudnorm
  │   lim_stage = limit(threshold/attack/release, s)          лимитер, live (нативный)
  │   s = switch(panel_lim_on): lim_stage ↔ s
  │   proc = s
  └─ switch(track_sensitive=false, panel_bypass)              live-BYPASS: raw_input ↔ buffer(proc)
  → output.icecast (fallible=true)                            FDK-AAC → ADTS → Icecast
```

Особенности, выясненные при портировании:

- ffmpeg-фильтры в Liquidsoap работают только поверх raw-формата: источник оборачивается
  в `ffmpeg.raw.encode.audio`, обработка — вложенными вызовами фильтров поверх графа
  (let-переменные неизменяемы), выход — через `source({audio=…, metadata=…, track_marks=…})`
  и `ffmpeg.raw.decode.audio`. Метаданные ICY проходят сквозь конвейер без изменений.
- Все параметры передаются геттерами `() -> float` (сама функция, не вызов — иначе
  значение «запекалось» бы при старте): `amplify(panel_gain, …)`, `gain=panel_eq_<f>`,
  `threshold=panel_comp_threshold`, `gain=panel_comp_makeup`, `threshold=panel_lim_ceiling`.
  Геттеры перечитываются каждый кадр — подстройка слышна сразу.
- `loudnorm` в динамическом режиме (`linear=false`) — пригоден для live-потоков, но
  нативного живого эквивалента не имеет: остался единственным фильтром ffmpeg-графа,
  его параметры (i/tp/lra) применяются при перезапуске воркера. Сама секция
  loudnorm включается/выключается живьём — общим механизмом выключателей секций.
- Нативные `compress`/`limit` принимают пороги в дБ напрямую (конверсия 10^(dB/20),
  нужная ffmpeg-фильтрам, больше не требуется); makeup у `compress` — это `gain` (дБ).
- `buffer(proc)` после `ffmpeg.raw.decode.audio` разводит clock-контекст: граф живёт
  во вложенном clock, дальше идут нативные операторы главного clock.
- Каждый вызов `on_metadata` печатает теги источника (`[metadata] …`) в лог воркера —
  StreamTitle виден в панели.
- Кодирование — FDK-AAC: `%fdkaac(channels=2, samplerate=44100, bitrate=128, afterburner=true)`.

Изоляция: каждый воркер — отдельный контейнер со своим watchdog, логом, счётчиком
рестартов и своим BYPASS. Открытых портов у воркера нет: он тянет источник снаружи
и пушит на Icecast наружу. Единственное исключение — telnet-сервер управления
Liquidsoap: `settings.server.telnet` на порту 1234, публикуется на хосте строго
на `127.0.0.1` со случайным портом (панель находит его через Docker API).

## Живое управление работающим воркером (Liquidsoap, без перезапуска)

В сгенерированном скрипте усиление — интерактивная переменная
`panel_gain = interactive.float("panel_gain", <линейное>)`, применяемая через
`amplify(panel_gain, proc)` (геттер, не вызов) после EQ и до компрессора. Все
10 полос EQ — интерактивные переменные `panel_eq_<частота>` (включая нулевые
полосы: их можно поднимать с нуля живьём). Компрессор — нативный `compress` с
переменными `panel_comp_threshold/ratio/attack/release/makeup`, лимитер —
нативный `limit` с переменными `panel_lim_ceiling/attack/release`: движение
ползунков в панели подстраивает их на работающем воркере без перезапуска.
Каждая включённая при старте секция оборачивается своим переключателем
`switch(track_sensitive=false, panel_<секция>_on)`: галочки секций в панели
(EQ, усиление, компрессор, loudnorm, лимитер) включают и выключают их
живьём, без перезапуска воркера — по той же схеме, что и общий BYPASS.
Параметры loudnorm (i/tp/lra) по-прежнему применяются только при
перезапуске. Обработанный сигнал собирается в отдельную ветку `proc`,
а выход воркера — `switch` на переменной `panel_bypass`: переключатель
BYPASS в шапке панели работает живьём для запущенной Liquidsoap-станции
и ортогонален секционным выключателям (BYPASS обходит всю цепочку целиком,
выключатель секции — только свой этап). Автоприменение слайдеров
(усиление, EQ, компрессор, лимитер), кнопка **«⚡ Живьём»**, пресеты
EQ, галочки секций и переключатель BYPASS шлют:

```text
POST /api/streams/<id>/adjust      {"gain_db": 3.0}
POST /api/streams/<id>/adjust      {"eq_gains": [0,0,6,0,0,0,0,0,0,0]}
POST /api/streams/<id>/adjust      {"compressor": {"threshold": -24, "ratio": 6,
                                                    "attack": 3, "release": 200, "makeup": 2},
                                      "limiter": {"ceiling_db": -3, "attack": 2, "release": 80}}
POST /api/streams/<id>/adjust      {"sections": {"compressor": false, "loudnorm": true}}
POST /api/streams/<id>/bypass      {"enabled": true|false}
  → 200 {"ok": true, "mode": "live", ...}
  → 409 (воркер не запущен / ошибка telnet)
  → 400 (пустой /adjust; неверный список eq_gains / объект compressor|limiter /
         неизвестная секция в sections)
```

Панель выполняет `var.set panel_gain = <линейное>` /
`var.set panel_comp_<парам> = <дБ>` / `var.set panel_lim_<парам> = <дБ>` /
`var.set panel_<секция>_on = true|false` / `var.set panel_bypass = true|false`
по telnet (усиление переводится в линейное `10^(dB/20)`, диапазон ±24 дБ;
параметры динамики клампятся в безопасные диапазоны); значения одновременно
сохраняются в `streams.json`, чтобы рестарт поднялся с ними. Ограничения:

- только воркер должен быть запущен (движок всегда Liquidsoap);
- работает только при локальном демоне Docker: при `DOCKER_HOST` порт мапится
  на удалённом хосте и живьём не достичь — API вернёт 409;
- живой выключатель секции появляется в скрипте, только если секция была
  включена при старте воркера: если переменной `panel_<секция>_on` нет,
  API вместо ошибки отвечает «секция сохранена — включится при перезапуске
  воркера», и значение сохраняется в реестре;
- live-BYPASS появляется в скрипте, только если в цепочке есть хотя бы один
  включённый этап обработки (иначе обход уже и так полный);
- ветка BYPASS ссылается на `raw_input` (сырой вход, захваченный до цепочки),
  а не на `s`: к концу цепочки `s` уже переприсвоен секционными switch-ами
  и равен обработанному сигналу — без `raw_input` BYPASS переключал бы
  «обработка ↔ обработка»;
- `buffer(...)` в ветках switch разводит clock-контекст: после ffmpeg-графа —
  перед нативными операторами, во второй ветке BYPASS — иначе Liquidsoap
  падает с «Cannot unify two nested clocks».

## Реестр станций

Настройки хранятся в `streams.json` рядом с `app.py` (в контейнере — на томе `/data`):

- `settings.ffmpeg_path` — общий путь к FFmpeg (только для подслушки A/B);
- `streams` — независимые станции: `id`, `name`,
  `bypass`, источник, EQ, компрессор, громкость (`gain`), LUFS, лимитер,
  кодирование, Icecast, автоперезапуск. Поле `engine` сохранено для
  совместимости и всегда нормализуется в `liquidsoap`.

Если обнаружен старый одиночный `config.json`, он однократно мигрирует в `station-1`;
исходный файл не удаляется. Старые HTTP-маршруты `/api/config`, `/api/start`, `/api/status`,
`/api/logs` и `/api/listen/<which>` продолжают работать с первой станцией.

Переменные окружения:

| Переменная           | Назначение                                             |
|----------------------|--------------------------------------------------------|
| `HOST` / `PORT`      | адрес и порт панели (по умолчанию 127.0.0.1:8770)      |
| `STREAMS_PATH`       | путь к `streams.json` (в compose — `/data/streams.json`) |
| `LEGACY_CONFIG_PATH` | путь к старому `config.json` для миграции              |
| `WORKER_RUNTIME_DIR` | каталог рантайм-скриптов `.liq` воркеров; путь должен быть виден демону Docker |
| `WORKER_BIND_ROOT`   | хостовый путь того же каталога для bind source, когда панель в контейнере (иначе не нужен) |
| `WORKER_IMAGE`       | образ воркера Liquidsoap (по умолчанию `audio-worker:2.4.2`) |
| `DOCKER_HOST`        | удалённый демон Docker, напр. `tcp://host:2376`        |

Основные маршруты:

```text
GET/POST       /api/streams
GET/PUT/DELETE /api/streams/<id>
POST           /api/streams/<id>/start|stop|restart
GET            /api/streams/<id>/status|logs|listen/<input|output>
POST           /api/streams/<id>/command
GET            /api/health
```

## Проверки

После установки зависимостей:

```bat
python -m unittest discover -s tests -v
```

Unit-тесты используют временный реестр и мок-клиент Docker,
не трогая пользовательский `streams.json`.

Песочница (end-to-end, требует Docker и локальный FFmpeg для синтетического источника):

```bat
python tests\sandbox_liquidsoap.py     :: две станции на Liquidsoap-воркерах
```

Песочница поднимает синтетический AAC-источник, панель и фейковый Icecast и проверяет:
пуш валидного ADTS, прохождение StreamTitle, изоляцию станций друг от друга,
автоперезапуск и маскировку пароля. (`tests\sandbox_integration.py` — устаревший
харнес этапа с FFmpeg-процессами, оставлен как базовый класс для песочницы.)

## Автозапуск в Windows

- Простой вариант: ярлык на `run.bat` в «Автозагрузке» (Win+R → `shell:startup`).
- Как служба (без окна консоли): **NSSM** —
  `nssm install AudioPanel "C:\Python312\python.exe" "C:\path\to\app.py"`.
- Контейнерный вариант: `docker compose up -d` (панель поднимется сама, см. restart-политику).

## Примечания

- Панель слушает только `127.0.0.1` — снаружи недоступна. Пароли Icecast хранятся
  в `streams.json` в открытом виде: не раздавайте этот файл.
- Порядок фильтров важен: эквалайзер → усиление → компрессор → loudnorm → лимитер.
  Лимитер стоит последним, чтобы нормализация не поднимала пики после ограничителя.
- Изменения настроек применяются при следующем (пере)запуске выбранного пайплайна.
- Усиление (`gain`, дБ) настраивается в карточке «02 Эквалайзер» и применяется
  в одной точке цепочки: после EQ, до компрессора.
- Тег `StreamTitle` идёт сквозь конвейер Liquidsoap автоматически и публикуется
  сервером Icecast от клиента `output.icecast`.
- Telnet API воркера поднят: живая подстройка усиления и полос EQ (`/adjust`,
  кнопка «⚡ Живьём», слайдеры EQ), живые параметры компрессора и лимитера,
  живое включение/выключение секций (галочки EQ, усиления, компрессора,
  loudnorm, лимитера) и живой BYPASS (`/bypass`, переключатель в шапке) —
  см. раздел выше.
- В песочнице Liquidsoap-потребление источника идёт быстрее realtime
  (авто-синхронизация под медленный источник не срабатывает) — компенсируется
  троттлингом источника в тесте. Против реального Icecast проверено не было.
