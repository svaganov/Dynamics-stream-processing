# Установка на новый ПК или сервер

Система: панель управления (Python + Flask) и воркеры обработки.
Движок один — **Liquidsoap** в Docker (по контейнеру на станцию);
FFmpeg нужен только для подслушки A/B (в контейнерном варианте он уже
внутри образа панели).

---

## Вариант 1 — контейнерный (рекомендуется)

На чистой машине нужен **только Docker** (+ Git, чтобы забрать код):
панель, FFmpeg для подслушки и всё остальное — внутри контейнеров,
на хост ничего не ставится.

### 1. Установите Docker

| Платформа | Что ставить | Где взять |
|---|---|---|
| Windows | **Docker Desktop** (с WSL2) | https://www.docker.com/products/docker-desktop/ |
| Linux | **Docker Engine** + compose-плагин | https://docs.docker.com/engine/install/ |

### 2. Заберите код и запустите

```bash
git clone https://github.com/svaganov/Dynamics-stream-processing.git
cd Dynamics-stream-processing
docker compose up -d --build
```

Первый запуск скачает базовые образы (несколько сотен МБ) и соберёт
образы панели и воркера — нужен интернет. Образ воркера
`audio-worker:2.4.2` панель **собирает сама** при старте, если его нет
(отключается `WORKER_AUTO_BUILD=0` в `docker-compose.yml`).

Панель: **http://127.0.0.1:8770**

> **Про docker.sock.** Панель монтирует сокет демона Docker, чтобы
> создавать и останавливать воркеров. Это даёт контейнеру панели права
> уровня root на хосте — осознанная цена такой оркестрации. Запускайте
> образ только из этого репозитория. На SELinux-хостах (RHEL/Fedora)
> добавьте `:z` к маунту сокета в `docker-compose.yml`.

### 3. Перенос настроек со старой установки (если была)

Реестр станций в контейнерном варианте живёт в томе `panel-data`.
Скопируйте старый `streams.json` в том один раз:

```bash
docker run --rm -v panel-data:/data -v "%CD%":/src alpine cp /src/streams.json /data/
```

(на Linux вместо `%CD%` — `$(pwd)`). После этого перезапустите панель:
`docker compose restart`.

## Вариант 2 — панель напрямую на хосте

Подходит для разработки и отладки. Воркеры всё равно в Docker — он нужен
в любом случае.

### 1. Что должно быть установлено

| Компонент | Зачем | Где взять |
|---|---|---|
| **Python 3.9+** | панель управления | https://www.python.org/downloads/ — при установке отметить «Add python.exe to PATH» |
| **Docker Desktop** (Windows, с WSL2) или **Docker Engine** (Linux) | воркеры Liquidsoap — по контейнеру на станцию | https://www.docker.com/products/docker-desktop/ |
| **FFmpeg**, full-сборка | подслушка A/B (MP3-мониторинг в браузер) | https://www.gyan.dev/ffmpeg/builds/ (в full-сборке есть `libfdk_aac`) |
| **Git** | получение кода | https://git-scm.com/ |

### 2. Получение кода и зависимости

```bat
git clone https://github.com/svaganov/Dynamics-stream-processing.git
cd Dynamics-stream-processing\app
pip install -r requirements.txt
```

Зависимости панели — всего две: `flask`, `docker` (Python-клиент Docker API).

### 3. Сборка образа воркера (один раз)

Из корня репозитория, при запущенном Docker:

```bat
docker build -t audio-worker:2.4.2 worker\
```

Базовый образ `savonet/liquidsoap:v2.4.2` скачается автоматически (~1 раз).
Проверка: `docker images` должен показывать `audio-worker  2.4.2`.

### 4. Запуск панели

**Windows:** дважды кликните `app\run.bat` — он проверит Python/FFmpeg,
поставит зависимости, поднимет сервер и откроет браузер.

Вручную (Windows/Linux):

```bat
cd app
python app.py
```

Панель: **http://127.0.0.1:8770** (порт меняется переменной `PORT`,
адрес — `HOST`; например `HOST=0.0.0.0` для доступа из сети).

## Образ анализатора (опционально, для обоих вариантов)

Кнопка «Анализ уровня и громкости» в Stream Info поднимает отдельный
контейнер-анализатор (dBFS, LUFS, спектр). Его исходники входят в этот
репозиторий (`analyzer\v2`), внешние проекты не нужны. Без образа кнопка
выдаст ошибку, остальное работает как обычно.

Из корня репозитория, при запущенном Docker:

```bat
docker build -f analyzer\Dockerfile -t audio-analyzer:2.0-panel .
```

Проверка: `docker images` показывает `audio-analyzer 2.0-panel`.
Анализатор стартует по кнопке в Stream Info, смотрит выходной поток
станции и останавливается кнопкой «Остановить анализатор»
(или при удалении станции).

## Первая настройка (5 минут)

1. Откройте панель → «+ Поток».
2. На странице станции заполните **01 Источник** (URL входного потока)
   и **07 Настройка подключения к Icecast** (хост, порт, маунт, логин/пароль
   вашего Icecast — локального или внешнего).
3. **08 Служба** (только хостовый вариант): если FFmpeg не в PATH —
   укажите путь к `ffmpeg.exe` (нужен для подслушки A/B).
4. Нажмите **▶ Старт**. Карточка на дашборде должна стать зелёной
   (жёлтая — нет подключения к Icecast, красная — нет входа).

Если источник или Icecast на той же машине — адреса `127.0.0.1`/`localhost`
указывайте как есть: панель сама перепишет их для контейнеров.

## Где лежат данные

| Вариант | Реестр станций (`streams.json`) |
|---|---|
| Контейнерный | том Docker `panel-data` (`docker volume inspect panel-data`) |
| Хостовый | `app/streams.json` — **бэкапить в первую очередь** |

Рантайм-скрипты воркеров (`runtime/`) пересоздаются автоматически.

## Обновление

```bash
git pull
docker compose up -d --build      # контейнерный вариант
docker build -t audio-worker:2.4.2 worker/   # хостовый вариант
```

Затем перезапустить станции (кнопка «⟳ Перезапуск» у каждой).

## Порты и сеть

- `8770` (или ваш `PORT`) — веб-панель. В хостовом варианте по умолчанию
  слушает только `127.0.0.1`; для доступа из сети — `HOST=0.0.0.0` и
  правило файрвола. В контейнерном варианте порт публикуется на все
  интерфейсы хоста (поменяйте `"8770:8770"` на `"127.0.0.1:8770:8770"`
  в compose, если это не нужно).
- Контейнерный вариант: telnet воркеров живёт только во внутренней сети
  `audiopanel_net`, наружу не публикуется. Хостовый вариант: telnet-порты
  воркеров публикуются только на `127.0.0.1` хоста.
- Исходящие соединения: к входному потоку (URL источника) и к Icecast-серверу.

## Если что-то не так

- **«FFmpeg не найден»** (хостовый вариант) — путь к `ffmpeg.exe` в разделе
  08 Служба.
- **Станция не стартует, в логе ошибка Docker** — Docker запущен?
  Образ воркера собран (в контейнерном варианте смотрите лог панели:
  `docker compose logs panel` — там строки `[entrypoint]`)?
- **Карточка жёлтая** — нет подключения к Icecast: проверьте хост/порт/пароль
  в разделе 07 и сам Icecast.
- **Карточка красная** — входной поток недоступен: проверьте URL в разделе 01
  (включите «Резерв при обрыве входа», чтобы эфир не падал).
- **Название трека (StreamTitle) не доходит до слушателей на Icecast 2.5.0** —
  известная регрессия самого сервера 2.5.0: он принимает обновления метаданных
  (пишет в лог и в `x_icy_title` статистики), но не вставляет их в поток для
  legacy-форматов (AAC/MP3). Панель передаёт StreamTitle источника корректно —
  на Icecast 2.4.x и icecast-kh слушатели видят названия треков. Решение:
  Icecast 2.4.4 / icecast-kh либо ждать исправления в 2.5.x.
- Лог станции: страница станции → «Команда и лог».
